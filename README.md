# Riiid Answer Correctness Prediction — аналитика удержания пользователей

## Как удержать пользователя в обучении?

**Анализируем путь пользователя, чтобы находить точки оттока и факторы, которые помогают дольше оставаться в обучении.**

### 🔗 Интерактивный дашборд

👉 **[Открыть Streamlit Dashboard](https://riiid-answer-correctness-prediction-shoklszb2utudzhnxbj7xe.streamlit.app)**

## О проекте

Проект посвящён анализу поведения пользователей образовательной платформы на основе данных **Riiid Answer Correctness Prediction**.

В данных представлены последовательности действий пользователей:

- ответы на задания;
- правильность ответов;
- время ответа;
- просмотр лекций;
- характеристики вопросов и образовательных тем;
- порядок взаимодействия пользователя с платформой.

Главная особенность данных — зависимость событий во времени: каждый следующий ответ пользователя связан с его предыдущей историей обучения. Поэтому в проекте используются не только простые агрегаты, но и пользовательские и тематические аналитические витрины.

---

## Бизнес-цель

Основной вопрос проекта:

> **Как удержать пользователя в обучении?**

Мы рассматриваем удержание как одну из ключевых точек роста образовательного продукта.

Дашборд помогает ответить на несколько связанных вопросов:

- как быстро пользователи прекращают обучение;
- сколько пользователей продолжают обучение спустя N дней;
- сколько пользователей доходят до N решённых вопросов;
- связана ли длительность обучения с успешностью;
- какие темы оказываются наиболее сложными;
- как скорость ответа связана с правильностью;
- отличается ли успешность после просмотра тематической лекции.

Полученные наблюдения могут использоваться для поиска точек роста **retention**, вовлечённости и качества образовательного контента.

---

## Что показывает дашборд

### 1. Retention по длительности активности

Показывает долю пользователей, чья наблюдаемая история активности длится не менее N дней.

Например:

> retention = 30% на 90-м дне означает, что у 30% пользователей наблюдаемая история активности продолжалась не менее 90 дней.

Это **не классический Day-N retention**: график не утверждает, что пользователь был активен именно на N-й день.

### 2. Retention по количеству вопросов

Показывает долю пользователей, которые дошли минимум до N решённых вопросов.

Например:

> retention = 40% на 100 вопросах означает, что 40% пользователей решили не менее 100 вопросов.

Метрика позволяет увидеть, на каких этапах взаимодействия с заданиями происходит наиболее заметный отток.

### 3. Успешность в зависимости от длительности обучения

Пользователи группируются по длительности активности:

- 0 дней;
- 1–7 дней;
- 8–30 дней;
- 31–90 дней;
- 91–180 дней;
- 181–365 дней;
- 366–730 дней;
- 731+ дней.

Для каждой группы рассчитывается взвешенная **Accuracy**:

```text
Accuracy = SUM(correct_answers) / SUM(questions_count)
```

Размер точки на графике отражает количество пользователей в группе.

### 4. Самые сложные образовательные темы

Для каждой темы рассчитывается:

```text
Difficulty = 1 - Accuracy
```

На дашборде отображаются темы с наиболее высокой сложностью при достаточном количестве наблюдений.

### 5. Типы ответов в зависимости от скорости

Ответы разделяются на быстрые и медленные, после чего сравниваются доли:

- правильных быстрых ответов;
- неправильных быстрых ответов;
- правильных медленных ответов;
- неправильных медленных ответов.

График помогает искать паттерны, связанные с уверенностью пользователя, сложностью задания и временем ответа.

### 6. Просмотр лекций и качество ответов

Для образовательных тем сравниваются:

- Accuracy после предыдущего просмотра тематической лекции;
- Accuracy без предыдущего просмотра лекции.

Каждая точка на scatter plot соответствует отдельной теме.

Точки выше диагонали `y = x` соответствуют темам, где наблюдаемая Accuracy после лекции выше.

> Важно: график показывает наблюдаемую связь, а не причинный эффект. Различия могут быть связаны с составом пользователей, сложностью вопросов и стадией обучения.

## Аналитические витрины

Для дашборда используются заранее подготовленные агрегированные таблицы.

### `mart_users`

Одна строка — один пользователь.

Используется для анализа:

- количества решённых вопросов;
- количества просмотренных лекций;
- Accuracy;
- длительности активности;
- прогресса пользователя;
- retention.

### `mart_questions`

Одна строка — один вопрос.

Содержит характеристики вопроса и агрегаты по ответам пользователей:

- количество попыток;
- Accuracy;
- Difficulty;
- время ответа;
- статистики правильных и неправильных ответов.

Используется для KPI, фильтрации вопросов и анализа скорости ответов.

### `mart_topics`

Одна строка — одна образовательная тема.

Используется для:

- оценки сложности тем;
- сравнения Accuracy;
- анализа взаимодействия с лекциями;
- оценки результатов после просмотра тематического контента.

## Ограничения анализа

При интерпретации результатов важно учитывать несколько особенностей:

- наблюдаемая длительность активности не равна классическому календарному retention;
- сравнение пользователей после лекции и без лекции не является A/B-тестом;
- различия между группами могут быть связаны с разной сложностью вопросов и составом пользователей;
- агрегированные показатели не всегда отражают индивидуальную динамику конкретного пользователя.

Поэтому результаты дашборда используются прежде всего для **поиска продуктовых гипотез**, которые затем можно проверять дополнительным анализом или экспериментами.
